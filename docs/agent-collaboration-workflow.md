# Agent 协作流程

仅在用户采用此流程时使用；读取文档本身不授权新增任务、提交或推送。
技术约定只维护在 [AGENTS.md](../AGENTS.md)，工具参数见 [tools.md](tools.md)，
模块地图见 [ARCHITECTURE.md](ARCHITECTURE.md)。中文沟通，代码和字段名保持原文。

## 1. 先核对事实

- MCP URL 由操作者提供，或在 Bridge 主机用 `open-bridge url` / `open-bridge prompt`
  获取。共享示例只写 `<MCP_URL>`，不要保存实例凭据、个人路径或临时调试脚本。
- 使用 Streamable HTTP；客户端/SDK 负责协议协商、JSON/SSE 和有效会话。
  ngrok 请求可附 `ngrok-skip-browser-warning: 1`，认证按实例配置提供。
  状态型客户端先握手，收到会话过期后重新握手，不猜测或重用失效 id。
- 用 `bridge_status{section:"overview"}` 核对实例，运行构建应为
  `state:"running"` 且 `build_stale:false`。首次接手调用一次 `workspace_brief`；
  Shell 方言以连接说明为准。
- Agent 本地沙箱不等于 Bridge 仓库。通过真实 MCP 工作区审计、编辑、测试和执行 Git，
  核对分支、提交、`git status` 和用户最近选择。文件读取/检索优先专用工具。
  旧任务清单与提交事实不一致时，不重复执行已完成工作。

## 2. 选择与授权

用户已明确目标、约束并要求执行时，直接继续，不为形式重复提问。
方向或行为影响确实需要选择时，只问一次，提供 **2–4 项**，每项说明：
推荐性、理由、范围/行为影响、验证和重启需求；允许用户给出自定义方向。

选定后连续执行，不再展示第二份实施计划或等待第二次确认。
只读授权不包含编辑、构建或提交；有新范围或破坏性影响时不能借旧选择扩大授权。
以最小直接的修改解决确认的问题，没有缺口就如实报告，不为产生提交制造改动。

## 3. 执行闭环

1. **审计**：对照实现、schema、说明、测试与真实现象；测试证据要求以 `AGENTS.md` 为准。
2. **实现**：只改本工作组范围，保留现用接口、权限、兼容行为和用户已有修改。
3. **验证**：执行定向测试和完整 `npm run release:check`。先构建再跑依赖 `dist/` 的集成测试；
   失败先找根因，不能重试到绿，也不能把条件跳过说成已经验证。
4. **审阅**：检查 `git diff --check`、变更范围、文本编码与 `git status`，调用 `review_changes`。
   它的累计窗口可能包含旧提交；本轮范围以当前差异为准。
5. **提交**：在已获提交授权时只暂存本组文件，英文信息说明行为和原因；确认工作树状态。
   不自动推送、不改写历史。
6. **运行验证**：运行产物变化且 `build_stale:true` 时，提交后请操作者重启，
   不自行停止承载当前连接的 Bridge。用户说“已重启”后先检查状态，再真实验证核心行为。
7. **推进**：真实验证通过后，用户已给下一方向就直接接续；否则给下一工作组的一次性选项。
   不自动替用户选择新工作，也不只停在完成汇报。

根目录 `AGENTS.md` 在发现/初始化时读取，上限 8,000 字符。
仅更新这些文字且未重建运行产物时，可通过新会话/重新发现验证，无需为文字单独重启进程；
旧会话已收到的说明不会自动替换，必要时直接读取最新版。源码测试通过、新构建已加载、
真实 MCP 行为通过是三种不同证据，分别报告。

### 长任务与恢复

多步工作开始前用 `set_todos` 写下完整清单，推进时整表替换（操作者 TUI「任务」只显示这份清单，不写就等于停了）；`report_progress` 报瞬时进度，不能代替清单。相关调用使用
`batch` 或 `run_script`，仍须返回必要事实。构建、测试等长命令使用
`run_command{background:true}`；构建加 `resource_keys:["build:dist"]`，保存 `command_id`，
以 `wait` / `read_process_output` 续读。前台超时不会杀进程。

SSL EOF、连接重置或传输超时不等于工具业务失败。等待 **5 秒**后重试一次；
若命令或写入可能已经执行，先查进程/活动/文件状态，有 id 就沿原任务恢复，
不能复制启动第二个有副作用的任务。

## 4. 汇报与交接

先说行为变化和用户需要做什么，再给验证、提交号和必要风险。不默认贴转义 JSON 或
大段原始日志，也不声称未执行的验证。交接至少保留：

- 当前目标、验收条件、用户选择及约束；
- 已改文件、检查结果、提交号和工作树状态；
- 是否待重启、未完成的真实验证、下一步。

临时进度保存在当次任务/交接记录，不写回本文冒充长期事实。
