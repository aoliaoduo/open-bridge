# Agent 协作流程

本文件用于开始工作、恢复压缩后的会话或交接给另一位 Agent。它保存可复用的协作规则，**不保存实例凭据、个人机器路径或当前工作组的完成状态**。

项目内部约定见 [AGENTS.md](../AGENTS.md)，模块边界见 [架构说明](../ARCHITECTURE.md)，具体工具行为见 [工具参考](tools.md)。以中文沟通，代码、命令和字段名保持原文。

## 1. 连接与事实来源

### 连接当前实例

由操作者提供 MCP URL，或在 Bridge 主机运行 `open-bridge prompt` / `open-bridge url` 获取。客户端配置示意如下；传输字段的具体名字以客户端支持的格式为准：

```json
{
  "mcpServers": {
    "open-bridge": {
      "transport": "streamable-http",
      "url": "<MCP_URL>",
      "headers": {
        "ngrok-skip-browser-warning": "1"
      }
    }
  }
}
```

完整 MCP URL 含访问能力，不能提交到公开文档、issue 或截图；示例一律用占位符。`ngrok-skip-browser-warning` 用于 ngrok 转发；认证头按操作者当前配置提供，不自行关闭认证或轮换令牌。

优先使用 MCP 客户端/SDK 管理协议协商、JSON/SSE 与会话。手工调试 2025 世代时：先 `initialize`，保存响应的 `Mcp-Session-Id`，发送 `notifications/initialized`，后续请求使用该有效会话；会话过期或 Bridge 重启后重新握手。不要猜测 session id，也不要假定某个 Agent 环境中的临时调用脚本一定存在。

### 每次恢复时确认事实

| 要确认的事实 | 来源 |
| --- | --- |
| 当前实例和构建 | `bridge_status{section:"overview"}`；健康标准为 `state:"running"` 且 `build_stale:false` |
| 真实工作区 | 首次接手调用一次 `workspace_brief`；后续参考 `bridge_status.workspace_root` |
| Shell 方言 | 当前连接的服务端说明，不按操作者机器或 Agent 本地环境猜测 |
| 当前分支、提交与未提交修改 | 通过 MCP `run_command` 执行 `git status --short`、`git log` 等 |
| 当前工作组与进度 | 用户最近选择、当前任务清单、实际差异和验证记录 |

Agent 的本地沙箱不等于 Bridge 主机上的仓库。真实仓库的审计、编辑、测试、Git 状态和提交，均以 MCP `run_command` 访问的工作区为准；文件读取和检索可使用专用工具。旧 todo 或旧交接记录与提交事实不符时，先核对，不能重复执行已完成工作。

## 2. 一次选择，连续执行

每个新工作组开始前先做**最小只读审计**，然后只问一次选择题，提供 **2–4 项**。每项必须说明：是否推荐、理由、范围/行为影响、验证方式和是否需要重启。用户也可以直接给出自定义方向。

用户一旦选择，连续完成审计、实现、测试、完整发布验证、审阅和提交；**不再给第二份实施计划或等待第二次确认**。进度更新不是新的审批。已有明确选择时直接继续，不重复询问。

执行原则：

- 先核实事实；只修复有证据的问题，改动保持最小、直接。没有发现缺口就如实汇报，不为产生提交制造改动。
- 保持现有工具名称、权限模型、公开契约和测试覆盖，除非本工作组明确要求改变；“旧”或“兼容”本身不是删除理由。
- 不恢复已删除的 `tool-run-hints` 行为教练层，不引入没有第二个现实实现的抽象层。
- 新的回归测试先在未修复代码上证明会失败，再修复并确认转绿；遵守 `AGENTS.md` 的测试约定。
- 多步工作用 `set_todos` 维护完整清单，用 `report_progress` 报瞬时进度；相关调用优先 `batch` 或 `run_script`，不要隐藏必要结果。
- 只读工作组不修改文件、不构建、不提交。其后续开发是另一工作组，不能借只读授权执行。

## 3. 标准工作闭环

1. **选择**：完成上述一次性选项环节。
2. **审计**：对照实现、公开 schema/说明、已有测试与真实现象；可以安全复现时先复现。
3. **实现**：修复确认的问题，保持并发、权限、顺序、错误提示和既有契约。
4. **定向验证**：执行受影响的单元、集成或 UI 测试。集成测试读取 `dist/`，源码改动后先构建。
5. **完整验证**：运行 `npm run release:check`。失败先找根因，修复本工作组造成的回归后重新验证，不能简单重试到绿。
6. **审阅**：检查 `git diff --check`、差异范围、正反向路径和 `git status`；调用 `review_changes` 展示累计改动。
7. **提交**：只提交本工作组文件，英文提交信息说明行为和原因；保留用户已有修改，不提交缓存或构建产物。
8. **重启与真实验证**：涉及运行构建、注入说明或 `build_stale:true` 时，提交后明确请操作者重启，不自行重启承载当前连接的 Bridge。
9. **推进**：用户回复“已重启”后，先核对 `bridge_status`，再通过真实 MCP 验证核心行为；验证通过后自动给出下一个工作组的一次性选项，不只停在完成汇报。

### 长命令与传输恢复

构建、测试、迁移等耗时不确定的命令使用 `run_command{background:true}`；构建附加 `resource_keys:["build:dist"]`，立即保存 `command_id`，随后用 `wait` / `read_process_output` 续读。前台等待超时不会杀掉进程。

SSL EOF、连接重置或传输超时不等于业务工具失败。等待 **5 秒**后重试一次；若原请求可能已启动命令或完成写入，先查进程、活动或文件状态，**不得复制启动第二个有副作用的任务**。有 `command_id` 就沿该 id 恢复。

## 4. 汇报与交接

面向非技术操作者，先说明行为变化和用户需要做什么，再列简洁的验证结论、提交号及必要风险。

必须区分：

- 源码/定向测试/完整发布检查通过；
- 当前运行的 Bridge 是否已加载新构建；
- 重启后的真实 MCP 核心行为是否已验证。

不声称未实际执行的验证，不默认粘贴 JSON 转义后的原始日志。交接应包含当前目标与验收条件、用户约束、已改文件、测试结果、提交号、工作树状态、重启要求、待做的真实 MCP 验证和下一步；未完成项不能省略。临时状态放在当次交接/任务记录中，不写回本文件伪装成长期事实。

## 5. 可复制提示词

### 开始或恢复

```text
读取并遵守 docs/agent-collaboration-workflow.md 和 AGENTS.md。
以当前 MCP 指向的真实仓库为准，先核对实例、构建与 Git 状态。
当前目标：<目标与验收条件>。
已明确的用户选择或约束：<填写；没有则说明>。
若是新工作组，给出一次性选项；已有选择就直接执行，不再二次确认。
```

### 已选定方向

```text
我选择 <选项或自定义方向>。按既定流程直接完成审计、实现、
定向测试、完整 release:check、审阅和提交，不再给实施计划或要求第二次确认。
```

### 操作者已重启

```text
已重启。先用 bridge_status 确认 running 且 build_stale:false，
再真实验证刚完成的核心场景；通过后自动给出下一工作组的一次性选项。
```

### 仅查看

```text
这是只读审计：不要修改、构建或提交。检查 <范围>，
给出事实、风险和有依据的后续候选，不贴大段原始日志。
```
